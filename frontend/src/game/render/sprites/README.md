# Aikido Parry: character sprites

These sheets are **placeholder art**, generated by `frontend/scripts/draw-game-sprites.py`.
An artist can replace them with hand-drawn sprites. As long as the rules below are kept, the
game picks up the new art with no code changes.

All characters are original designs for this project. Please keep them original (no characters,
costumes or sprites from other games) and keep them suitable for children aged 10 and up: no
weapons, no blood.

## Files

| File | Character |
|---|---|
| `male.png` | The player: male aikidoka (white gi, dark hakama) |
| `female.png` | The player: female aikidoka (white gi, dark hakama, ponytail) |
| `walker.png` | Troublemaker who walks in and punches (cap and jacket) |
| `dasher.png` | Troublemaker who also does the whirlwind kick (spiky hair, headband, jersey) |
| `sprites.json` | Frame size, feet point, scale and the list of frame names per sheet |

## Frame rules

- **Size**: every frame is **80 × 78 pixels**. Frames sit side by side in one row, in the order
  listed in `sprites.json` (frame 0 at x = 0, frame 1 at x = 80, and so on).
- **Feet point**: the point between the character's feet, on the floor, is at **(36, 74)** in
  every frame. The game places this point on the character's position.
- **Facing**: draw every frame **facing right**. The game mirrors frames when a character faces
  left. (One exception: `spinBehind` is part of the spin and is drawn as it should look.)
- **Scale**: 1 pixel = 3 game units. A standing character is about 45 pixels tall.
- **Background**: transparent. PNG, no smoothing; the game scales it up with crisp pixels.
- **Not in the frames**: the yellow "!" warning, health pips, glows and smoke. The game draws
  those itself.

## Replacing the placeholders

1. Draw the frames in the order above and save each sheet with the same file name.
2. If a sheet gains or loses frames, update its `frames` list in `sprites.json`, keeping the
   names used above. A frame the game asks for but can't find is drawn as a plain block, so a
   missing frame is easy to spot.
3. Run the game (`npm run dev`, then `http://localhost:5173/game/`) and the tests (`npm test`).
   The renderer tests check that every frame the game uses exists in `sprites.json`.
4. Once real sprites are in, stop running `scripts/draw-game-sprites.py`, since it would
   overwrite them.
